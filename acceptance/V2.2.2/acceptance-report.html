三、风险与待确认

# 事项 等级 建议
R1 递交流程中仅剩「PM验收新增/变更、反馈 / TB验收需求」两环节未实测写入：二者需以「制作完成的需求」为前提（需走拆解→制作→完工全链造出样本），本轮立即解决的反馈为「无需拆解」不产生制作需求，故暂无可验收样本；其余环节（TB提反馈/PM立即解决/TB申请递交/PM审批递交/QA递交）均已真实写透 中低（数据状态盲区） 需时造一条完整制作完成需求后补验 PM验收/TB验收（后端放行原理已由 B1 证实）
R2 「逃逸Bug」模块选项本轮验到其在反馈模块枚举中落地，但 dev 所述「后续统计 bug 逃逸率」的统计出口/看板本版未涉及 低（覆盖盲区） 待逃逸率统计功能上线时单独验证其取数是否以该模块为分组依据
R3 「特殊事项需同步」保存时，项目编辑表单会校验其它必填项（如「场景美术」），若原项目该字段为空则需一并补齐才能保存 低（口径待确认） 确认是否设计如此（编辑必须全表单合规）；本轮已按流程补齐后正常保存
R4 审批递交申请(PM) 页清空「选择PM」筛选后列表拉取报错崩溃（getApplyPublishList → applyMixins.js:74 JSON.parse(undefined)），需先选定 PM 才能查 低（健壮性） 前端对空 PM 筛选参数做容错，避免 JSON.parse 未定义崩溃

未覆盖盲区声明：反馈递交流程的各写入环节未用 PM/白名单账号逐环节真实提交（见 R1）；逃逸Bug 逃逸率统计出口未验（见 R2）；主题皮肤逐套视觉渲染效果未逐一切换核对；排期模式的实际拖动落库创建任务未做（仅验模式进出与提示，拖动创建为鼠标连续手势，自动化不稳，且创建走 schedule 已有链路）。

新增功能

需关注人员：PM、TB\BD、QA、组长

1.「项目反馈-递交流程」：（让每条反馈从提出到验收有据可查，减少遗漏与重复沟通）
支持 TB 提交项目反馈并推送 PM 审核，PM 可对反馈进行「拆解」（选择岗位专业、任务模块、工时，一次拆成多个制作需求并指派给不同制作人员）或「立即解决」；
支持 TB 申请递交时自动同步项目的新增/变更与反馈内容、严格勾选本次递交项，经 PM 审批、递交排期落地后由 QA 完成项目递交；
支持 PM 对新增/变更与反馈进行验收（正常/提前/滞后）、TB 对制作完成的需求进行最终验收确认；

2.「项目反馈-逃逸Bug 分类」：（沉淀逃逸缺陷分类，支撑 bug 逃逸率统计）
支持 PM 在拆解反馈需求时将反馈模块标记为「逃逸Bug」，作为后续统计 bug 逃逸率的数据来源；

3.「项目-特殊事项提醒」：（项目关键事项在列表即时可见，减少沟通遗漏）
支持在编辑项目信息时开启「特殊事项需同步」并填写提醒内容，保存后项目列表的项目名称旁展示提示图标，点击即可查看特殊事项详情；

4.「排期-拖选批量排期」：（连续时段一次成批排期，减少逐格重复操作）
支持在排期表进入「排期模式」后，拖动鼠标选择同一行的连续单元格，快速创建项目/非项目任务；
