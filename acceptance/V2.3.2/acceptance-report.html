二、缺陷清单（已确认的问题，需修）

复现/接口/定位等技术细节见 fix-handoff.md。

# 缺陷 严重度 建议
B1 项目概览-概况「成本预警」双口径卡片的"实际花费/产出类型人天"口径严重偏小、结论方向反了（医科大#6653 显示实际花费 84.5h/结余 91%，同口径实际应为超支）。沿用 V2.3.2-pre 缺陷，本轮 API 复核仍未修复。 严重 成本预警卡实际花费/产出工时应与人员页、需求与成本页同源（去掉非产出人员后的产出工时），修正后重校"超支/结余"结论方向
B2 项目概览-质量 玉禾田#6651「项目反馈总数 1」与「反馈验收状态分布合计 0」同页两处对不上，点查那 1 条反馈的验收状态无数据。沿用 V2.3.2-pre 缺陷。 一般 统一「项目反馈总数」与「反馈验收状态分布」的数据源，确保总量=各状态之和
B3 模型外包-查看日报抽屉：在抽屉内「快捷添加新反馈」成功后，对应模型任务卡的「N 条反馈」计数不实时刷新（仍显旧值，关闭并重开抽屉才更新为正确值）；反馈本身已正确落库。 轻微 快捷添加反馈成功后就地刷新当前任务卡的反馈计数（或整卡数据），无需用户重开抽屉

三、风险与待确认

# 事项 等级 建议
R1 AI 自动填充项目动态：AI 实际解析并回填会议表单的结果本轮未能实测——模型服务（deepseek-v3）在跨数分钟多次尝试中持续返回 429「请求过于频繁」，ai_skill/execute 恒返 status:llm_error。功能的 UI/流程/接口/agent 异步任务机制均已验证到位，仅 LLM 回填结果因模型配额限流未观察到（环境类盲区，非代码缺陷）。 中 确认模型服务配额/限流策略；建议在模型持续 429 时给出「切换模型/稍后重试」的更明确引导，并在配额充足时段复验一次真实回填质量（会议类型/内容/参会人/待办的识别准确度、人员按系统昵称匹配率）
R2 项目概览-完全重构：V2.3.2-pre 报告另记录 7 项风险/待确认（R1 反馈跨模块口径、R2 BUG 月度 vs 全量口径、R3 项目价值清单为硬编码示例、R4 未绑定需求展示策略、R5 产出工时占比列未实现、R6 时间轴 vs 递交次数口径、R7 不存在项目返 ORM 原始错误串）。本轮沿用，详见 V2.3.2-pre 报告 §三。 中 参见 V2.3.2-pre 报告逐项建议

未覆盖盲区声明：① AI 自动填充的真实 LLM 回填结果因模型服务持续 429 未能实测（R1）；② 项目概览深度验收沿用 V2.3.2-pre，本轮仅对严重缺陷 B1 做 API 复核确认仍存，未重跑全部 7 子页跨模块对账；③ 快捷添加反馈的截图上传（Ctrl+V 贴图）分支未强制走文件上传；④ 反馈走查留言的 500 字上限、并发多人留言时序未专门构造。

四、发版内容（初稿，待人工定稿）

体验升级、重构优化

需关注人员：PM、组长、场景组、DTA、Builder/供应商

1.「模型外包-查看日报」：（减少日报多时的翻找成本，提升场景、DTA 走查与反馈协作效率）
将发包列表的"查看日报"由弹窗重构为右侧抽屉，按模型分组以摘要态卡片呈现（模型名称、制作状态、日报数、反馈数、制作进度），支持按模型/建筑名称搜索、按制作状态筛选，并逐卡展开查看日报明细；

该发包的反馈走查留言在"反馈管理-验收工作台"批量验收时一键查看，方便场景、DTA 与供应商在验收环节直接对齐意见。

需关注人员：PM、全员

AI 赋能

需关注人员：PM

1.「项目动态-AI 自动填充」：（免去 PM 会议纪要手工誊抄，提升会议动态录入效率）
