## B1（严重）项目概览-概况「成本预警」实际花费/产出工时口径错误、超支误判为结余

- **归属**：项目概览（新）→ 项目概况 → 成本预警双口径卡片（`project_overview/get_header` 的 `cost_compare`）。**沿用 V2.3.2-pre 缺陷**，本轮 API 复核确认仍未修复。
- **复现**：
  1. 打开 `/project/project_overview_new?projectId=6653`（重庆医科大附二院项目，已结项）→ 项目概况。
  2. 看「成本预警」卡：显示 实际花费 84.5h（10.56 天）、产出类型工时 83h（10.38 天），标准人天 986h（123.25 天），判「结余 91%」（`over:false`）。
- **接口原文**（`GET /manage_api/project_overview/get_header?project_id=6653`，2026-08-17 复核）：
  ```json
  "cost_compare": {
    "algoA": {"label":"标准人天 vs 实际花费人天","stdDays":123.25,"actualDays":10.56,"diffDays":112.69,"over":false,"desc":"标准人天 986h÷8=123.25天；实际花费人天 84.5h÷8=10.56天"},
    "algoB": {"label":"标准人天 vs 产出类型人天","stdDays":123.25,"outputDays":10.38,"diffDays":112.87,"over":false,"desc":"标准人天 986h÷8=123.25天；产出类型工时 83h÷8=10.38天"}
  }
  ```
- **预期 vs 实际**：按卡片 tooltip 声明口径（已过滤非产出人员 PM/管理层），医科大#6653 人员页实际工时合计≈894h、产出型需求实际工时≈1,181h，均 > 标准 986h → **应为超支**；卡片却显示实际花费 84.5h（偏小约 10~14 倍）并判"结余 91%"，结论方向反了，直接误导成本/工时管理判断。同功能内（成本预警 vs 需求与成本页 vs 人员页）自相矛盾。
- **定位线索**：`cost_compare.actualDays/outputDays` 的取数源与需求与成本页 `get_req_cost`（consumed_hour：6653=1387）、人员页产出工时不同源，疑似漏聚合或误用了某单一子集工时。
- **通过标准（可执行断言）**：`get_header?project_id=6653` 的 `cost_compare.algoA.actualDays*8` 应与人员页去非产出人员后的实际工时合计一致（≈894h 量级、非 84.5h），且当实际/产出工时 > 标准工时时 `over:true`（超支）；玉禾田#6651 同理（实际花费应≈1006.5h 量级）。

## B2（一般）项目概览-质量 反馈总数与反馈验收状态分布不自洽

- **归属**：项目概览（新）→ 质量 → 项目反馈总数 / 反馈模块饼 / 反馈验收状态分布（`project_overview/get_quality`）。**沿用 V2.3.2-pre 缺陷**。
- **复现**：打开 `/project/project_overview_new?projectId=6651`（玉禾田，进行中）→ 质量子页；「项目反馈总数 1」「反馈模块饼 场景 1」，但「反馈验收状态分布」待交付/待验收/已验收合计=0；点该 1 条反馈的验收状态无数据。
- **预期 vs 实际**：同一实体（项目反馈）同页两处数字应自洽——总数=各状态之和。实际 总数 1 ≠ 状态分布合计 0。
- **通过标准**：`get_quality?project_id=6651` 中「项目反馈总数」= 「反馈验收状态分布」各档之和；玉禾田#6651 那 1 条反馈应落入某一验收状态档。

## B3（轻微）模型外包-查看日报抽屉：快捷添加反馈后任务卡反馈计数不实时刷新

- **归属**：模型外包 → 发包列表「查看日报」抽屉（`src/views/routerViews/outsource_project/components/PackageDailyReportDrawer.vue`）→ 任务卡「N 条反馈」meta chip；快捷添加反馈向导（提交走 `outsource_feedback/create_feedback`）。
- **复现**：
  1. `/project/outsource_project?projectId=6679` → 发包#31『半导体』行「查看日报(46)」→ 打开抽屉。
  2. 任意模型卡（如『有机通风柜』当前显「6 条反馈」）点「添加新反馈」→ 批量创建向导选模块+填内容 → 下一步 → 确认提交 → toast「成功创建 1 条反馈/反馈已提交」。
  3. 回到抽屉，该卡「N 条反馈」chip 仍显「6 条反馈」（未变 7）。
  4. 关闭抽屉、重新点「查看日报」→ 该卡正确显示「7 条反馈」。
- **预期 vs 实际**：快捷添加反馈成功后，当前任务卡的反馈计数应就地 +1；实际不刷新，需重开抽屉。反馈数据本身已正确落库（`get_feedback_list?outsource_task_id=195` 由 6→7，新反馈 #830）。
- **定位线索**：创建反馈成功回调未刷新抽屉内该任务卡的反馈计数（未重新拉 `get_feedback_list` 或未本地 +1）；抽屉初始化时的计数取自发包列表加载态，仅在抽屉重新打开时重算。
- **通过标准**：在抽屉内快捷添加 1 条反馈成功后，无需关闭重开，对应任务卡「N 条反馈」chip 立即由 N 变为 N+1。
