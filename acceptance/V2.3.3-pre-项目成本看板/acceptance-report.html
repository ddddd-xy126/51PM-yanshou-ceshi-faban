三、风险与待确认

# 事项 等级 建议
R1 「项目成本动态」看板的"产出工时(EV)"与「项目概况-成本预警」cost_compare.algoB"产出类型工时"同用"产出"字样但计算路径不完全同源：抽样 2 个项目两者差值方向不一致（#6710 为 -53h，#6713 为 +35.5h），说明并非简单的人群子集关系，而是两个功能各自独立定义的指标。两处计算本身经查均无错误，但同名/近名指标跨页面并存，容易让 PM 误判"两个页面数字打架"。 中（不影响本功能自身正确性，但影响跨页面解读体验） 建议产品侧二选一：① 在两处页面互相加一句跳转/说明（如"本页'产出工时'与项目概况'产出类型人天'统计口径不同，详见 XX"）；② 长期考虑统一底层"产出类"判定逻辑，避免同名指标分叉演进
R2 AI 分析功能（总览级"整体成本诊断" + 单项目级"开始分析本项目"）入口/交互正常，但当前账号生效模型（grok-3-mini）在验收窗口内持续返回 data.status:"llm_error"（"模型服务请求过于频繁 429"），未能实测真实归因结果质量 低（环境盲区，非代码缺陷，与 V2.3.2 轮 P-15 同类问题） 建议在模型配额充足时段人工复验一次实际分析内容的合理性；哨兵/自动化用例按惯例只守 data.status 契约，不死等 LLM 成功
R3 需求 2「AI 项目动态：飞书端 → 51PM Agent → 51PM 数据入库技术验证」用户明确本轮排除，由用户自行验证 — （范围调整，非风险分级项） 待用户自行验证后，如需要可反馈结果供后续沉淀
