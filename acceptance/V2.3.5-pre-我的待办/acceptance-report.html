二、缺陷清单（已确认的问题，需修）

# 缺陷 严重度 建议
B1 顶部「已逾期」Tab 高亮状态与筛选条件不会随点击其他顶部 Tab 正确重置/清除，与「待处理」组合时计算出的分类集合明显错误（缺失应有分类），导致用户看到角标显示"已逾期 1"却提示"没有符合当前筛选条件的记录"，造成数据丢失的误导 一般 前端修复顶部 Tab 互斥/组合逻辑：点击"待处理/待审批/未读通知"任一非「已逾期」态时，若期望与「已逾期」保持组合过滤，应保证 source_keys 计算逻辑对所有 4 种组合都正确（即「待处理+已逾期」应与单独点「已逾期」时的全量 11 key 一致）；若不打算支持组合过滤，则任一顶部 Tab 被点击时应无条件清除其余 3 个的高亮与筛选态
B2 「发包待结项」待办点击「前往原页面」仅跳转并定位到项目层级的模型外包列表（不筛选、不定位到具体记录），而同类功能「发包待立项」跳转会自动填充搜索框精确定位到目标记录（共1条）——两者体验不一致 轻微 参照「发包待立项」的跳转实现，为「发包待结项」跳转补充自动填充搜索框（发包名称）或直接高亮/滚动定位到目标发包行

修复交接：各缺陷的复现步骤、定位线索与修复通过标准见 fix-handoff.md（给前后端开发，可整份投喂 AI）。

三、风险与待确认

# 事项 等级 建议
R1 「已闭环」视图默认仅展示近 30 天关闭的待办（滚动窗口），且页面无任何可见 UI 控件（未找到日期选择器/更多筛选入口）可调整该范围，超过 30 天的历史闭环记录当前无法通过「已闭环」Tab 查看 中 需产品确认：若为有意的性能/简洁性设计，建议在页面上明确提示"仅展示近30天"；若非有意，建议补充日期范围选择器
R2 「口径与角色」说明弹窗中 moment_mention 一行文案称"现表没有已读标记字段，未读需后端新增读取记录表后才能落地"，与实测 mark_read 已真实生效且持久化矛盾，判断为文档滞后未同步 低 建议开发同步更新弹窗文案，避免误导后续验收/开发人员对该功能实现状态的判断
R3 task_review（第 12 个 source_key）仅存在于 get_count 接口返回中，从未出现在任何 get_list 请求的 source_keys 参数里，也不属于任何顶部 Tab/侧栏分类，「口径与角色」说明弹窗也未提及，是一个当前 UI 完全无法触达的孤立字段 低 建议确认是否为遗留废弃字段；若已废弃建议后端一并从 get_count 的 counts 返回中移除，避免误导
R4 hour_todo（工时相关待办）无独立顶部 Tab 或侧栏分类入口可单独查看，「口径与角色」说明弹窗也未记录其推送条件与操作角色；当前测试账号该分类计数为 0，未能验证其真实 UI 呈现 低 建议确认其入口设计是否符合预期（如是否应归入某个现有分类，或需要补充独立入口/说明文案）

1.「我的地盘-我的待办」：（一站式待办中心，减少员工在多个模块间来回排查"我还有什么没处理"的成本）
新增待办中心页面，顶部按「待处理/待审批/未读通知/已逾期」四态统计当前用户全部待办事项，侧栏按业务来源分类展示（发包待立项/发包待结项/动态提及我/BUG指派/BUG验证/风险动态/递交审批/发包审核/需求验收/反馈拆解/工时待填 等）；
点击任意待办可在右侧详情面板查看摘要，并可一键「前往原页面」跳转到对应模块的原始业务页面处理；
支持标记已读、按截止时间排序、按关键词搜索；已处理完成的待办统一归档至「已闭环」视图供事后追溯（默认展示近 30 天）。

A.1 老功能回归

「我的待办」为跨模块只读聚合层（除 mark_read 标记已读一处写操作外无其他写路径），不修改任何既有模块自身的业务逻辑，故本轮以「逐分类跨模块独立取数核对」（详见 §一.2/§一.3/§一.4/§一.6，4 组抽样全部一致）替代传统「精准回归选集」。另跑 npx playwright test "tests/api-.*\.spec\.js" 全量接口冒烟：73 通过 / 1 跳过 / 1 失败。失败项 tests\api-v2.3.2.spec.js:79 断言 ai_skill/execute(intent=moment_meeting_ai_fill) 返回体应含 data.status 字段，实测返回空对象 {}；该接口属于 V2.3.2 版本的 AI 会议纪要自动填充功能，与本轮「我的待办」无代码交集，结合既往台账记录（P-15：AI 模型服务持续 429 限流）判定为已知环境问题，非本轮改动引入的回归。跳过项为既有用例的常规跳过（需「制作中」发包样本前置条件），与本轮无关。
