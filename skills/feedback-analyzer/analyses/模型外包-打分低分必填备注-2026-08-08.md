# 用户反馈需求分析

模型外包：外包任务评分≤3分需强制填写备注说明原因以便追溯（疑似已在结项评价打分环节实现，需人工确认是否为历史遗留数据或存在未覆盖的打分入口）

来源反馈：2026-08-08 模型外包反馈（截图为「半导体」项目外包任务管理列表视角）

## 1. 问题分析

外包任务列表中存在评分≤3分（如截图 `ZK_BDT_QXT` 2★）却查不到备注说明的记录。反馈截图取自「发包详情 → 任务管理」列表的「质量评分」列（只读展示列），该列本身不展示备注，也看不出这条评分是何时、经何入口录入的，导致后续复盘/追责时无据可查。

## 2. 影响功能

模型外包 → 「结项评价打分」（制作中发包「打分」操作入口）；模型外包 → 发包详情 → 任务管理「质量评分」展示列。⚠️ 需人工确认：反馈验收工作台（通过/驳回流程）是否是另一条能产出「质量评分」但未被本反馈诉求覆盖的入口。

## 3. 用户诉求

希望任何≤3分的质量评分都必须附带备注说明原因，保证低分记录可追溯，避免"有分无据"。

## 4. 原因分析

「质量评分」这项数据可能存在多个录入/展示环节（打分提交入口 vs 列表只读展示列），但强制备注的校验目前只加在「打分提交」这一个环节上，产品设计上没有覆盖「所有能产生该评分数据的入口都要有同等约束」这一诉求；同时列表侧的展示设计也没有同步考虑「评分旁边要能看到备注」这一可追溯性需求。⚠️ 需人工确认：反馈里的低分样本，究竟是规则上线前的历史遗留数据、还是当前确实存在未覆盖校验的入口——两种情况的原因不同，需先核实再定性。

## 5. 需求方案

建议：① 先核实反馈方是否知晓「结项评价打分≤3分必填备注」规则已上线，若已上线且反馈截图属于历史遗留数据，可考虑标记为规则生效前数据、不强制补录；② 若排查发现存在其他能产出质量评分但未受该校验保护的入口，建议对该入口比照现有规则补齐同等的强制备注校验；③ 在「任务管理」列表的「质量评分」列上增加备注可见入口（如 hover 提示或点击展开），方便直接在列表侧回溯原因，无需跳转到打分弹窗。
