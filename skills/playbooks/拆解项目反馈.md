# 拆解项目反馈 / 立即解决（PM 处理反馈，含逃逸Bug 模块）【写】

> 一句话：PM 对 TB 提交的项目反馈做处理——「拆解」成一个或多个制作需求并指派，或「立即解决」填结论关闭；反馈模块可标记为「逃逸Bug」用于统计 bug 逃逸率。典型 AI 复用场景：「把某条待审核反馈立即解决 / 拆解指派」。
>
> ⚠️ **写操作**：拆解/立即解决不可逆（立即解决后无法再编辑或拆解）；提交前把「反馈 + 处理方式 + 结论」给用户 AskUserQuestion 确认。

## 参数

| 参数 | 示例 | 说明 |
| --- | --- | --- |
| `env` | `test`（默认） | 测试 `10.67.8.183:7777` |
| `feedback_id` | `569` | 目标反馈 id（`get_apply_demand_list` 的 `id`）|
| `action` | `solve` / `split` | 立即解决 / 拆解 |
| `solution` | `经复现为已知逃逸Bug，最新构建已修复` | 立即解决的解决方案内容（必填）|

## 入口

- **入口**：我的地盘 → 我的信箱 →「拆解项目反馈」tab；行内「拆解」/「立即解决」；「反馈模块」筛选下拉含 UI/其他/功能/场景/底板/建模/特效/**逃逸Bug**
- **路由**：`/my_board/main/myMessageBox`（⚠️ 子页直接 URL 会重定向回 main，必须点左侧菜单「我的信箱」）
- **等待锚点**：`waitForURL(/myMessageBox/)` + `waitForTimeout(1500)`
- **进站**：先按 [../README.md](../README.md) Tab 复用；`goto /my_board/main/main` 后 `.el-menu-item:has-text("我的信箱")` 点击进入

## 操作步骤（真实 UI）

1. `goto /my_board/main/main` → 点左侧菜单「我的信箱」→ 落「拆解项目反馈」tab
2. 筛选：搜索项目 / 反馈模块（枚举含逃逸Bug）/ 申请状态（PM审批中·已沟通解决·已通过·**待PM审批**）/ 日期
3. 目标反馈行操作列两按钮：
   - **拆解**：`splitApply(row)` 开向导 → 选岗位专业/任务模块/工时 → 可拆成多条制作需求指派不同人 → `submitSplitForm` 提交（需求类型「反馈」直接建任务，「新增/变更」需关联项目需求）→ 状态转「已通过」
   - **立即解决**：`handleSolveApply(row)` 开弹窗 → 填解决方案内容（必填）→「立即解决」→ 确认框「确定」→ 状态转「已沟通解决」
4. 反馈审批状态：待PM审批 / 已通过（查看拆解结果）/ 无需拆解·已沟通解决（查看原由）

## 步骤

### ⚠️ 权限/可见性门禁与绕过（本轮实测）

「拆解项目反馈」队列**按 PM 作用域**：非该项目 PM（如邓欣羽）看不到别人项目的待审核反馈、按钮亦按 `systemRole` 禁用。造数/复现时绕过（台账 P-13）：

// 1) 后端取回目标反馈完整行（页内 fetch 被 CORS 拦，用 node 侧 / api spec request）
//    GET /manage_api/produce_demand/get_apply_demand_list?page=1&limit=50 → 找 id===feedback_id
// 2) 直调组件方法打开处理弹窗（绕过可见性+按钮禁用）
const findVM = (pred) => { const seen=new Set(); let t=null; const walk=(v,d)=>{ if(!v||d>15||seen.has(v))return; seen.add(v); if(pred(v))t=v; for(const c of v.$children||[])walk(c,d+1); }; walk(document.querySelector('#app').__vue__,0); return t; };
const vm = findVM(v => v.$options?.methods?.handleSolveApply && v.applyForm);

## 🚨 防手滑（写操作强制）

- **立即解决不可逆**：确认框「立即解决后无法进行编辑和拆解」是最后关口；提交前 AskUserQuestion 确认
- 造数造在合适反馈上并带版本前缀（如解决方案写「V2.2.2验收-…」），不清理
- ⚠️ 后端未校验 PM 白名单（B1 同类）：非 PM 绕过后 `solution_apply_demand` 仍放行——这是缺陷线索，不是「功能可用」

## 可直调接口（免 UI 快路径）

- 列表：`GET /manage_api/produce_demand/get_apply_demand_list?page=&limit=`（`data.data` 为列表；字段 `id/apply_demand_status(待PM审批/PM审批中/已沟通解决/已通过)/apply_demand_module[]/pm/apply_name/apply_demand_desc/solution_content`）
- 立即解决写入：`POST /manage_api/produce_demand/solution_apply_demand`（payload=applyEditData + 解决方案）
- 反馈提交（TB 侧上游）：`POST /manage_api/produce_demand/add_apply_demand`

## 读数 / 断言锚点

- 反馈模块枚举：`.el-select-dropdown:not([style*="display: none"]) .el-select-dropdown__item` 应含「逃逸Bug」
- 立即解决落库：`get_apply_demand_list` 中该 id 的 `apply_demand_status==='已沟通解决'` 且 `solution_content` 非空

## 已知坑

- ⚠️ 子页直接 URL / router.push 重定向回 main，必须点左侧菜单进入
- ⚠️ 队列按 PM 作用域 + 按钮 `systemRole` 门禁；造数走 handleSolveApply/splitApply 直调（台账 P-13）
- ⚠️ 清空「选择PM」筛选会使 `getApplyList`（applyMixins.js:66）`JSON.parse(undefined)` 崩，须先选 PM 或用 UI 下拉真实选状态
- ⚠️ 逃逸Bug 是反馈模块专有枚举，不在 `index/get_task_options` 任务选项树
