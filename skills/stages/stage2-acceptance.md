# 阶段 2 执行文档 · 新功能验收（完整细则）

> 本文件是 [总控 SKILL](../SKILL.md) 阶段 2 的**唯一执行细则**（单一出处）。拆验收清单模板见 [stage01-regression.md](stage01-regression.md) ①（阶段 1① 已产出并落盘）；发版内容初稿与转 HTML 见 [stage3-release.md](stage3-release.md)；发版撰写规范（分类/强度/句式/红黑榜）查表仍引 [release_notes.md](../release_notes.md)。
>
> **一句话**：以真实用户身份逐个功能操作，每个功能过「UI 流程 / 边界 / 接口层 / 数据一致性」四层取证，每条需求用三轴下结论，产出验收报告 md（有缺陷另出 fix-handoff.md）。

## 0. 铁律：必须走真实 UI 交互

README 里"首选 Vue data 直写"的规则**在验收中反转**：

| 用途 | 允许的手段 |
| --- | --- |
| 操作功能（点击、输入、切换、拖拽） | **只能走真实 DOM 交互**（`click` / `type` / 键盘事件）——验收目的就是验交互本身，Vue 直写会把待验的交互层整个绕过去，等于没验 |
| 核对数据（列表条数、字段值、状态） | 可用 `js()` 读 Vue data 作辅助断言，但不代替 UI 操作 |

- 按钮用真实点击点不动——**这本身就是一个 🐛 BUG 发现**，记录下来，不要换 Vue 直写绕过去。
- **唯一例外：前置数据准备撞上权限门禁**（造前置数据的环节、非被验功能）遇前端角色/白名单禁用按钮（PM 审批 `systemRole!=='PM'`、QA递交 `testListRooters` 白名单）：**不切角色**（切回可能重新扫码、登录态报废，台账 P-05）、不对禁用按钮死循环重试；读按钮 Vue 组件找背后方法（如 `approvedApply(row)`）直调打开表单，后续表单交互仍走真实点击；同时把「前端禁用但后端放行」作为 ⚠️ 写进报告（后端缺校验线索）。被验功能本身的权限问题不得绕，记 ⚠️。
- **⚠️ 写链路必须写透**：测试库与生产隔离、数据不需清理，写操作（挂起/取消/提交/改状态/建数据）**必须真实提交并核对落库/联动**，停在"点了确认框没提交"＝没测。"怕污染真实数据"不是跳过理由。例外只有两个：①真正不可逆且无业务必要的极端破坏动作；②用户明确说本轮不用深入操作/只验展示层。

## 1. 前置（强制）

1. **按清单直接开跑**：清单已在阶段 1① 落盘 `.pipeline-state.json` 顶层 `checklist[]`（含「预判落库维度」），此处**从状态文件读清单**、不重拆、直接按清单逐项验收；查不到入口的标"待现场找"现场探索。一次只带 **1~2 个功能**，多了分批。**验收中实锤的落库口径若与清单预判维度不符，回到阶段 1③ 补跑差集簇的回归**（影响面纠偏闭环）。
2. **执行载体**：优先用 Copilot 浏览器工具（打开页面、点击、截图）现场探索；复杂流程可写临时 Playwright 脚本（复用 [helpers.js](../../regression/tests/helpers.js) 的坑规避封装：公告弹窗关闭、可见 dialog 过滤、双份渲染过滤等）。临时脚本验完即弃或直接进化为阶段 4 的正式用例。
3. **浏览器页签**：优先复用已共享的 51pm 页签；开新页签后**第一件事** `page.setViewportSize({width:1920,height:1080})`（默认 1280×720 会裁掉右侧栏、左侧仪表盘菜单不渲染）。
4. **登录态**：集成浏览器免扫码续登用 **CAS 种 cookie 法**（V2.3.0 轮实测：直接开静态页注入 localStorage 的 oauthToken 会被弹回 loginPage，已废弃）：① goto `https://cas-test.51aes.com/loginPage`，在 CAS 域 `document.cookie='SESSION=<state.json里的值>; path=/; domain=.51aes.com'`（**不带 secure**，authorize 走 http）；② goto `http://cas-test.51aes.com/oauth/authorize?client_id=vtWuKx7A&response_type=code&scope=all&redirect_uri=http://10.67.8.183:7777` → 免扫码带 code 回 app；③ 落回调页后**等 app 自己交换新 token**（别直接 goto /main，可能只渲染水印空壳）。临时 Playwright 脚本一律 headless + `storageState:'auth/state.json'`（与回归同，context 创建时注入、SPA init 不跳登录）。SESSION 也过期/续登失败才暂停问用户扫码（姿势见 [stage01-regression.md](stage01-regression.md) 阶段 0 退出码 2），不代输凭据。
5. **环境固定测试环境** `10.67.8.183:7777`，不再询问；仅用户明确说「正式环境」才切换（写操作逐项问）。后端 8888 需本机转发：`cd regression; npm run proxy` 常驻。
6. **入口先查表**：dev_notes 每条功能先查 [entry_map.md](../entry_map.md)；查不到的标"待现场找"直接现场探索（不等用户勾选）。归属实在无法推断才追问——优先查表而非满站猜。
7. **已知交互坑**（V2.2.6 轮实测）：①上传触发的 filechooser **必须消费**（`setFiles` 或开新页签甩掉），不消费会挂起、页面随机跳回 main、点击失灵；②节日主题动画（圣诞飘雪）令 `locator.click` 永远报「元素不稳定」，用 `force:true` 或坐标点击；③ `tb_publish` / `myMessageBox` / `my_board` 等子页直接 URL 或 `router.push` 会被重定向回 main，必须真实点左侧菜单（`el-menu-item` 的 vm.handleClick 可作兜底）。

## 2. 交付约定

- **提及实体一律给名称**：报告/消息引用项目、任务、需求、缺陷等实体时必须写「名称（#ID）」，如「任务『日报导出优化』(#12345)」；只给裸 id 用户看不懂。
- **产物路径**：报告与截图全部落盘 `acceptance/{版本}/`，给用户发路径用 `D:\project\51PM验收-测试-发版\acceptance\{版本}\`（Windows 格式）。
- **截图只留强相关**：只截三类——a) 功能验证关键结果页（每功能 1~2 张）；b) BUG 现场（必截）；c) 定妆图 final-\*。中间过程（下拉展开、每次输入、探索性打开的页面）**不截**（曾一轮截 60+ 张，远超需要）。
- **时间范围遵守页面提示**：设日期范围后若页面出现「日期范围过大/请选一个月以内」等提示，**立即缩小到要求范围重查**，不带禁用状态继续验（会漏验时间轴等联动）。通用原则：任何筛选后先读页面 warning/alert 文案再继续。

## 3. 逐项走流程 + 四层取证

每个验收项按"计划流程"用真实 UI 操作走一遍，检查维度：

| 维度 | 看什么 |
| --- | --- |
| 功能正确性 | 按钮/入口存在、点击有响应、流程能走通、无报错弹窗、无控制台红错 |
| 数据正确性 | 数字对得上（可交叉核对：看板汇总 vs 明细列表条数）、状态流转正确 |
| 交互体验 | 加载有反馈、操作路径顺不顺、有没有点了没反应/重复提交 |
| 内容合理性 | 文案有无歧义/错别字、字段口径怪不怪、与相邻功能是否矛盾 |
| 边界情况 | 空数据展示、超长文本溢出、特殊字符、翻页、筛选组合、日期跨月/跨年、0 与极大数值 |
| 接口层 | 关键操作时监听页面请求/响应（`page.on('request'/'response')` 或 `performance.getEntriesByType('resource')` 拿真实接口路径）；再**用 node 临时脚本 / `api-*.spec.js` 的 `request` fixture 直调**接口验边界参数（非法值、越权 id、空参）——⚠️**页内 `page.evaluate` 里 `fetch` 打 `localhost:8888` 会被 CORS preflight 拦**（多轮实测确认，台账 P-06 同源），故接口断言一律走 node 侧、不在浏览器页内做；鉴权 `Authorization: Bearer <oauthToken>`。**顺带记下该功能的「创建/更新接口」**（路径 + payload 形态 + 关键字段），哪怕本次只读——它是阶段 4「动作型自造」造前置数据的原料 |
| 数据一致性 | 前端展示 vs 接口响应 vs 跨页面交叉核对（看板汇总 vs 明细条数）；写操作后刷新页面确认落库 |

> ⚠️ **统计/看板类面板验收铁律（必做）**：验证数据正确性**不能只在该看板自家接口之间互证**（同源自证查不出跨模块口径分歧）。**必须去数据源头的其他业务模块独立取数、自行分组统计，再与看板逐项对账**：
> ① 识别看板每个指标的**源头模块**（如 BUG 看板 → BUG 系统 `bug/get_list`；递交指标 → 递交列表 `project_publish/get_list`）；
> ② 去源头模块拉全量记录，**自己按字段分组 count**（按项目/人/类型/状态/时间等看板的每个分组维度）；
> ③ 与看板数字**逐项 diff**，差异必须能**逐条定位解释**（如"看板递交 65 vs 列表 60 = 5 条计划时间为空的补录，看板是列表超集 → 正确"；"临时 12 vs 17 = 两模块判据不同 → 缺陷"）。
> 看板内部「总览 = 明细 = 图表加总」的自洽是**必要不充分**——它证明不了两个模块对同一业务概念是否用了相同口径。跨模块数字对不上 = 缺陷。

> 验收**不只是浏览器上点一遍**：四层是**验证证据**，不是报告主线。报告主线是「这条需求满不满足」（见 §5 模板各需求节标题结论）；四层证据压成功能节里四行「验证证据」，哪层验不了（无接口文档、无权限）标 ⚠️+原因，别静默跳过、别反客为主占标题层。
> **验证证据排版规则**：写成 `验证证据：` 下**四个子项各占一行**（`- UI ✅ …` / `- 边界 ✅ …` / `- 接口 ✅ …` / `- 数据 ✅ …`），每行**一句话说完**；本项无独立接口的层标 `—`，验不了的层标 ⚠️+原因。
> **接口测试的写位规则**：**明细归功能、发现归缺陷/风险、沉淀归附录**——① 属于某功能的接口验证（路径+参数+结果）直接写进该功能节「验证证据-接口」一格，不另开表；② 跨功能/不隶属单一功能的接口发现按确定性归 §二 缺陷或 §三 风险，**不单开「接口测试汇总」节**；③ 未覆盖范围写进 §三「未覆盖盲区声明」，api spec 指针+测试数据放附录 A；④ **禁止把 UI 验收结果换个说法当接口用例凑表**。同时：接口路径+参数+坑回填 [entry_map.md](../entry_map.md) 对应行备注，用例固化进 `api-v{版本}.spec.js`。

**截图规范**（`page.screenshot({path, type:'jpeg', quality:80})` 落到 `output_dir` 绝对路径）——**默认精简模式，截图是最大耗时项**：

```
{序号:02d}-{功能名}-bug-{简述}.jpg    # 异常图：发现问题必截，截到问题现场
final-{功能名}.jpg                    # 定妆图：每个功能 1 张，功能最完整的一屏，给发版文档用
{序号:02d}-{功能名}-{步骤描述}.jpg    # 过程图：仅两种情况才截——①写操作提交前后 ②用户明确要求"全程截图"
```

- 核对文本/数字/状态一律用 `page.evaluate` 读 DOM/Vue data 断言，**不要靠截图肉眼比对**；截图只留"人需要看的证据"（BUG 现场、定妆图）。
- **交付截图一律 headless + `storageState` 建 context 出图，禁集成浏览器、禁 favicon 手动注入 localStorage**（集成浏览器视口被 VS Code 回弹到 ~1390/1534→右侧留白，台账 P-09；favicon 注入赶不上 SPA 跳登录、截出扫码页）。姿势（与回归同）：`chromium.launch()`→`newContext({storageState:'auth/state.json',viewport:{width:1920,height:1080}})`→`require('./start-proxy').startProxy()` 起 8888→`goto` 即登录态（SESSION 过期不影响，鉴权走 Bearer）；`shot()` 断言 `innerWidth===1920` 才落图。
- **截图覆盖本轮全部功能，含 dev_notes 标「不参与发版初稿」的**（不参与初稿 ≠ 不截图）；每功能至少 1 张体现核心变更的定妆图，折叠外选项用 `locator('li:visible',{hasText}).scrollIntoViewIfNeeded()+click()` 选中让字段显示该值再截（别用 evaluate 滚下拉，不稳）。

**速度纪律**（防止一次验收拖数小时）：复验轮次默认 **1 轮**（只有想复现"偶发"BUG 才多轮）；一次消息只带 **1~2 个功能**（多了必撞迭代上限被截断）；数据核对用 `page.evaluate` 一次性批量读值断言，不逐条截图核对。

**⚠️ 筛选/搜索/日期范围类功能验收铁律（禁止空图收工）**：

- 验收带筛选条件的功能（超时/状态/日期范围/关键词等）时，**必须先设出能命中数据的条件，再勾选/搜索、再截图**；很多列表页有默认收窄条件（如递交列表默认只筛**当天**、今天大概率无目标记录），不设范围直接验会得到空列表。
- UI 层断言**不能只验"勾选/点击不报错"**——必须验"**真的筛出了预期的命中记录**"：断言列表**非空**且首行内容命中目标特征（如超时递交行「实际递交时间」列标红「超时递交」），最好同时抓「全量 vs 筛选集」两组条数确认是真子集。
- **截图前先确认列表有数据**（`page.evaluate` 读 tbody 可见行数 > 0 或分页 total > 0），空状态图（"暂无数据/共 0 条"）不得作为定妆图。
- 设日期范围属**前置数据手段**（日期 fill 不触发是已知坑，走 vm form+search 设范围），被验功能本身（勾选/筛选交互）仍走真实 UI 操作。

## 4. 结论分级（三条正交的轴，别混在一个符号里）

验收产出分三个**独立维度**，不要用一个 ⚠️ 兼职"没验到 / 拿不准 / 真风险"三件事：

**A. 验收结论（对每条需求）**——主结论，回答"这次交付达标没"，写进报告 §一 各需求节标题：

- ✅ **满足** — 功能实现了开发意图、业务上可用合理
- 🟡 **部分满足** — 主体达成但有缺口（如需求说"日报和花费"，只做了日报）
- ❌ **不满足** — 功能缺失 / 走不通 / 严重偏离需求

**B. 缺陷（BUG）**——已确认、无需产品拍板就知道要修的问题。**双载体分工**：报告 §二 只写产品经理能看懂的一句话 + 严重度（阻断/严重/一般/轻微）+ 建议；复现步骤、预期 vs 实际、定位线索、通过标准等技术细节写独立交接文档 `fix-handoff.md`（规范见 §5，给前后端开发整份投喂 AI），**同一信息只写一处，互不复制**。判定：功能走不通、报错、数据错、console 红错等 → 缺陷。

**C. 风险（Risk）**——不确定 / 待拍板 / 没验到的，写进报告 §三，按「影响 × 可能性」定级（高/中高/中/低）。常见三类（用于判断，不单列成表列）：口径待定（拿不准是 BUG 还是设计如此、需产品/后端确认，如"无 PM 项目可提交但不可见"）；覆盖盲区（agent 验不了或没验到——权限不足、时间/后端触发只能验展示层、视觉细节需人工、极限数据量没造）；健壮性（非阻断的接口/边界瑕疵，如不存在 id 返回空模板而非报错）。

> 关键边界：**"我没验到"是风险里的覆盖盲区，不是缺陷；"待产品确认口径"是风险，不是缺陷**——只有确定必修的才进缺陷。一条需求可以「✅满足」同时挂着若干风险（在功能节用"关联缺陷/风险：见 §三 Rx"指过去）。

## 测试数据策略

测试环境与正式环境**数据库完全隔离**，测试库里的"真实项目"只是副本——**可随便挑合适的项目直接写数据，无污染顾虑**，不需要专用测试项目。测试库会不定期整体刷新（先例：原测试项目 SJ202607100001 记录消失、#6712 易主），因此：
