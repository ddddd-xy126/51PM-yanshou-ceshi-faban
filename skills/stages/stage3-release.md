# 阶段 3 执行文档 · 发版（初稿必做，报告写全→转 html→交付）

> 本文件是 [总控 SKILL](../SKILL.md) 阶段 3 的执行入口。发版内容撰写规范**全文遵循** [release_notes.md](../release_notes.md)，本文件只管流程与交付动作，与其不重复。

1. **生成初稿**：验收报告写完后**直接生成，不等用户追问**；存在缺陷/风险待确认项时**照样产出**——正文按「已生效部分」的口径写，待确认的措辞留在报告 §二缺陷/§三风险里说明，不进对外正文。**只依赖两个输入：本轮验收结果 + [release_notes.md](../release_notes.md) 规范**（分类判断表 / 撰写铁律 / 强度规则 / 句式 / 红黑榜 / 命名规范，必须真正读取并逐条套用，不许凭感觉写）。**不读、不碰发版记录/发版.md——任何阶段都不碰**（定稿与归档由用户在发版管理自行完成，agent 只专注输出验收报告；历史版本归属拿不准时在初稿里标 ⚠️ 留待定稿判断，不去翻历史）。**具体撰写规则（分类以用户为准/价值描述/不参与初稿排除等）全部以 release_notes.md 为准，本处不复述**。

   落笔前必须逐条对照 release_notes.md 的 4 个高频判错点（读完规范再自查）：
   - **分类：新增功能 vs 体验优化** — 产出物是全新能力/独立模块/独立页面/独立文档位 → **新增功能**，哪怕挂在已有页面上、动机是"提升体验"也算新增（反例：`创建人员群组`、`项目测试文档` 是全新能力，别错判成体验优化）。
   - **影响强度** — 新增用户可感知的核心能力 → 至少**中等**，别保守判"较小"。强度按 **dev_notes 全部条目**判（dev_notes 即本次发版范围，不翻历史确认"全集"，范围存疑标 ⚠️ 留待定稿）。统一用 `较小/中等/较大`。
   - **BUG 转正向表述** — 对外发版**不暴露"曾出数据异常/误建"等负面信息**，把"修复了XX异常"改写成正向能力（如"仅支持在子需求下创建任务，规范需求选择范围"）；内部 BUG 放报告 §二/§三，不进对外正文。
   - **价值括号写业务结果，不写功能能力** — 写"降低XX创建成本/减少人工汇总/提高盘点效率"，不写"方便统一录入/支持XX"（能接在"支持"后的多半是功能能力，不合格）。

   写完后**用 release_notes.md 的「常见错误」表自查一遍**再交付。

2. **初稿写进验收报告**的「## 发版内容（初稿，待人工定稿）」节——不落独立文件；定妆图直接引用 `acceptance/{版本}/final-*.jpg`，不拷贝。⚠️ 版本块用 `###`/`####` 真标题分层，不要用 `**粗体**` 行冒充标题（否则 html 无层级、目录不可导航）。
3. **转 HTML（全流程唯一一次转换，发版初稿写回之后才转）**：至此报告 md 已写全（验收结论 + 各需求详情 + 缺陷/风险 + 发版初稿 + 附录回归），转成 html——md 与 html 是同一份完整交付物。**本机首选 `node scripts/md2html.js`**（标准库 markdown-it；pandoc 本机不可用、勿首选，台账 P-11）：

   ```powershell
   cd regression
   node scripts/md2html.js ..\acceptance\{版本}\acceptance-report.md ..\acceptance\{版本}\acceptance-report.html "51PM {版本} 验收报告"
   ```

   - md2html.js 开了 `html/linkify/breaks`：发版功能点多行「支持…」会紧凑成 `<br>`；表格/代码块/图片样式内置，无需额外样式文件；
   - md 里列表项内嵌表格时，表格前**必须空一行**（markdown-it/gfm 同坑），否则表格被压平成带竖线的段落文字；
   - 图片是相对路径引用，html 与截图同目录，双击即可带图浏览；对外发送时把整个 `acceptance\{版本}\` 目录打包；
   - 转换失败不阻断，md 仍是主产物；发版内容后续被人工定稿改回 md 后，重跑同一条命令重转 html；
   - **备选（仅 pandoc 可用的环境）**：`pandoc acceptance-report.md -f gfm -t html5 --standalone -H _report-style.html --toc --metadata title="51PM {版本} 验收报告" -o acceptance-report.html`（须带 `-H _report-style.html` 放宽 36em 正文宽 + `--toc`；样式文件缺失时先重建：写入 `<style>body{max-width:72em}table{display:table;width:100%}</style>` 到 `_report-style.html`；本机 pandoc 不可用，勿首选）。

4. **交付**：把报告与截图目录路径发回用户（Windows 格式 `D:\project\51PM验收-测试-发版\acceptance\{版本}\`）；定妆图不另行拷贝（发版内容直接引用 `final-*.jpg` 原路径，验收产物与发版素材同源）；有缺陷时提醒 `fix-handoff.md` 可直接转给前后端开发（整份投喂 AI），修复回传后走阶段 5。**至此对外交付物完成**，定稿与归档由用户在发版管理自行完成。
5. 若用户主动提供定稿与初稿的措辞差异，作为反例回填 release_notes.md 相应章节；若用户改了报告 md，重转一次 html 保持交付物同步。
